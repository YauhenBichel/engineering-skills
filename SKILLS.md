# Skills

| Area | Skill | When to use |
|---|---|---|
| Plan | [clarify-requirements](skills/clarify-requirements/SKILL.md) | Turns a vague request into a short, testable spec. Use at the start of any task whose goal, inputs, outputs or limits are not clear. |
| Plan | [break-down-work](skills/break-down-work/SKILL.md) | Splits a feature or project into small, ordered tasks that each end in something testable. Use before starting work that takes more than an hour. |
| Plan | [estimate-and-risks](skills/estimate-and-risks/SKILL.md) | Gives an honest estimate with ranges and the risks behind it. Use when asked how long something takes or whether it is feasible. |
| Design | [design-architecture](skills/design-architecture/SKILL.md) | Designs the structure of a system or component: parts, responsibilities, data flow, interfaces. Use for new systems or large changes. |
| Design | [write-adr](skills/write-adr/SKILL.md) | Records an architecture decision as an ADR. Use when a technical choice is made that others will later ask about. |
| Design | [design-api](skills/design-api/SKILL.md) | Designs an HTTP or library API: endpoints or functions, inputs, outputs, errors, versioning. Use before implementing a public interface. |
| Design | [model-data](skills/model-data/SKILL.md) | Designs a database schema or data model. Use when adding tables, collections or persistent formats. |
| Build | [implement-feature](skills/implement-feature/SKILL.md) | Implements a feature in an existing codebase, end to end, with tests. Use for any new behaviour. |
| Build | [write-python](skills/write-python/SKILL.md) | Writes idiomatic, typed, testable Python. Use whenever writing Python code. |
| Build | [write-go](skills/write-go/SKILL.md) | Writes idiomatic Go. Use whenever writing Go code. |
| Build | [write-typescript](skills/write-typescript/SKILL.md) | Writes safe, typed TypeScript for Node or the browser. Use whenever writing TypeScript or JavaScript. |
| Build | [write-sql](skills/write-sql/SKILL.md) | Writes correct, safe and efficient SQL and migrations. Use for queries, schema changes and data fixes. |
| Build | [write-cli](skills/write-cli/SKILL.md) | Builds a command-line tool that is pleasant for people and scripts. Use when creating a CLI. |
| Build | [concurrency](skills/concurrency/SKILL.md) | Writes correct concurrent or asynchronous code. Use for threads, async, parallel jobs, queues or shared state. |
| Build | [algorithms](skills/algorithms/SKILL.md) | Chooses and implements the right algorithm and data structure. Use for performance-sensitive logic or interview-style problems. |
| Quality | [write-tests](skills/write-tests/SKILL.md) | Writes useful automated tests. Use when adding behaviour, fixing a bug or covering untested code. |
| Quality | [debug](skills/debug/SKILL.md) | Finds the root cause of a bug methodically. Use for errors, crashes, wrong results or flaky behaviour. |
| Quality | [review-code](skills/review-code/SKILL.md) | Reviews a change for bugs and risks. Use for pull requests, diffs or code the user asks you to check. |
| Quality | [refactor](skills/refactor/SKILL.md) | Improves code structure without changing behaviour. Use when code is hard to change or read. |
| Quality | [performance](skills/performance/SKILL.md) | Makes code faster or lighter based on measurement. Use when something is slow or uses too much memory. |
| Quality | [security-review](skills/security-review/SKILL.md) | Checks code and configuration for security problems. Use before releasing anything that handles input, secrets, auth or money. |
| Quality | [handle-errors-and-logging](skills/handle-errors-and-logging/SKILL.md) | Designs error handling and logs that make failures visible and diagnosable. Use when writing code that can fail. |
| Ship | [git-workflow](skills/git-workflow/SKILL.md) | Commits, branches and pull requests done cleanly. Use for any version control work. |
| Ship | [ci-cd](skills/ci-cd/SKILL.md) | Sets up or fixes continuous integration and delivery. Use for GitHub Actions or other pipelines. |
| Ship | [containers-and-deploy](skills/containers-and-deploy/SKILL.md) | Packages and deploys services with containers. Use for Dockerfiles, compose, Kubernetes or a server deploy. |
| Ship | [dependencies](skills/dependencies/SKILL.md) | Adds, upgrades or removes dependencies safely. Use when changing what a project depends on. |
| Operate | [observability](skills/observability/SKILL.md) | Makes a service observable: logs, metrics, traces, alerts. Use when running anything in production. |
| Operate | [incident-response](skills/incident-response/SKILL.md) | Handles a production incident and writes the postmortem. Use when something is down or broken for users. |
| Operate | [data-durability](skills/data-durability/SKILL.md) | Protects data: backups, restores, migrations without loss. Use when data must not be lost. |
| Communicate | [write-docs](skills/write-docs/SKILL.md) | Writes documentation people use: README, how-to, reference. Use when documenting code or a project. |
| Communicate | [explain-code](skills/explain-code/SKILL.md) | Explains code clearly to another developer. Use when the user asks what code does or how it works. |
| Data | [data-analysis](skills/data-analysis/SKILL.md) | Analyses a dataset correctly and reports what it shows. Use for questions answered from data files or databases. |
| Data | [ml-experiment](skills/ml-experiment/SKILL.md) | Runs a machine-learning experiment that can be trusted. Use when training or evaluating models. |
| Research | [research-and-compare](skills/research-and-compare/SKILL.md) | Researches options and compares them to recommend one. Use when choosing a library, tool, approach or vendor. |
